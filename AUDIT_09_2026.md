## Backend: DB ↔ S3, транзакции

**B1. S3-put до DB-commit, orphan при любом сбое**
- `src/face_moment/inventory/photo_upload.py:123-134`: `stager.stage()` → `AtomicPhotoAdmission.admit()`
- `src/face_moment/inventory/admission.py:100-110`: `cleanup_losing_candidate` только в ветке дубликата
- Любой другой сбой между put и commit оставляет `candidates/<uuid>` без владельца. Чистит только операторский cleanup.

**B2. Дубликат только через `psycopg diag`, иначе 500 + мусор**
- `src/face_moment/inventory/admission.py:117-119`: проверка `error.orig.diag.constraint_name`
- Без `diag` повтор даёт 500 вместо `{"outcome":"duplicate"}`, staged-объект не удаляется.

**B3. Orphan cleanup блокирует все загрузки**
- `src/face_moment/inventory/orphan_original_cleanup.py:63-83`: блокирующий `pg_advisory_xact_lock` внутри `session.begin()`, затем `list_key_pages` по 4 префиксам + deletes в одной открытой транзакции
- Пока идёт: все upload падают в `OriginalCleanupUploadPausedError` (503). Открытая транзакция на сетевом I/O: рост `xmin`, блок VACUUM. На большом бакете — минуты простоя.

**B4. Realtime evidence: DB-ссылки без S3-объектов**
- Фоновый `attach_captures`: сначала commit манифеста `diagnostics/captures/{attempt}/{i}.jpg` в DB, потом S3 put
- Крэш между ними: висячие ссылки → `NoSuchKey`. Чистильщик их сохраняет, не чинит.

**B5. Retention: commit → delete → commit, двойной счёт**
- `src/face_moment/diagnostics/retention.py:110-132`: commit границы, цикл S3-delete, второй commit
- Крэш в середине: повтор добивает удаление, но два `RetentionCleanupLatest` покажут разный счёт за один attempt. `promo/retention.py:234-243`: диагностика отдельно от `delete(PromoAttempt)`.
