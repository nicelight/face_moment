# Capture identity

Операторское решение 2026-09-15: в «Библиотека → Медиа площадки» Admin
(существующие operator/developer роли) выбирает период, размечает найденные
лица загруженных фотографий людьми из глобального реестра. Одинаковые имена
не объединяют UUID. Связи используют существующие photo_faces, без копий
embeddings; удаление человека удаляет его связи, удаление фотографии исключает
её примеры. Старые строковые annotations не мигрируют в реестр.

Каждый присланный JPEG crop (до 20, никогда полный кадр) сохраняется отдельно
в private object storage. Capture metadata расширяет ordinary diagnostic
evidence. Подготовленные при native inspection embeddings живут только внутри
запроса; отдельная best-effort диагностика после ответа использует эти данные,
не вызывает shared native model и не влияет на Promo/search/QR. Совместимость
строго по pipeline revision. Score человека — maximum cosine по размеченным
активным примерам; победитель принимается при score >= immutable venue
similarity threshold. No-face, preparation unavailable/error, отсутствие
совместимых примеров и below-threshold различаются. Сохраняются threshold,
revision, score, person UUID и имя на момент диагностики. Это не обучение.
Для новых захватов сохраняются до трёх ближайших разных размеченных людей
(`nearest_people`), по maximum score на человека, с сортировкой по убыванию
score и UUID при равенстве. Список сохраняется и ниже порога; если лучший
результат ниже порога, статус остаётся «Не распознан». Карточка показывает
сходство, имя и последние шесть символов UUID,
как в списке людей; это короткий идентификатор, не компоненты embedding.
Исторические захваты без этих полей не пересчитываются.

Фактический top-five порядок передаёт processing в request-local observations.
UI сначала показывает «Выбраны для поиска», потом остальные в исходном порядке.
При незавершённом отборе порядок не реконструируется. Старые Attempts без JPEG
показывают отсутствие сохранённых изображений.

По уточнению оператора JPEG хранятся те же 90 суток, что ordinary Attempt.
Доступ к JPEG закрывается по общему сроку после Attempt, независимо от
времени физического удаления. Существующий periodic cleanup удаляет истёкшие
objects вместе с ordinary metadata по существующему Attempt retention. Все
маршруты private, mutations используют существующие session/CSRF и роли.

По уточнению KISS оценки «верно/неверно» и единый блок «Кого не нашли» (до 3
людей) являются временным состоянием страницы: редактируются/очищаются и
теряются при перезагрузке. Постоянные таблицы для оценок и архив Attempts не
создаются. Реестр людей и разметка остаются до ручного удаления. Старый сценарий
Calibration отключён отдельной последующей правкой; эти данные от него не зависят.

## Проверка и включение

Native integration: `tests/diagnostics/test_capture_identity.py` — настоящий
YuNet/SFace на локальном sample `skimage.data.astronaut`, отдельная PostgreSQL
с миграцией, private MinIO, восемь JPEG, labeling, server order, ранняя
финализация receipts, повторное чтение и общий retention. Browser rendering
test `tests/client/test_capture_identity.spec.mjs` использует HTTP fixtures
и отдельно проверяет порядок, временные оценки и узкий экран. Caddy routes
проверяются через отдельный временный HTTPS edge в существующем regression.

После уточнения оператора изменения применены к локальному стенду: migration
`0025_capture_identity_labels`, обновлённый образ backend/realtime/worker,
текущие Python/client исходники и Caddy matcher. Документированные source units
`deploy/systemd/system/face-moment-retention-cleanup.*` восстановлены; timer
установлен и включён в user systemd с локальным override на `.env.testing` и
Docker Desktop. Ручной запуск cleanup не выполнялся. Через обычный HTTPS
проверены медиатека, реестр, лица существующих фотографий и private JPEG,
список и карточка исторического Attempt. Старые JPEG не восстанавливаются
задним числом. Порядок повторного запуска — в [local development](../guides/local-development.md#capture-identity-и-порог-сходства--локальное-применение).

В библиотеке открыть «Медиа» нужной площадки и период загрузки фотографий.
У загруженной фотографии раскрыть «Разметить лица», выбрать человека или
«Новый человек». Пустой выбор удаляет связь. «Люди и разметка» позволяет
переименовать/удалить человека. Ниже расположен отдельный раздел «Захваты»;
его период относится ко времени Attempt. Здесь выводятся предложенные
identity и временные оценки. После переключения модели media/разметка
предпочитает существующий serving state, иначе использует admission state.
