# FT-004 — Scoped Realtime Search and Result Assembly

**Epic:** [EP-002 — Automatic Promo and QR Continuation](../epics/EP-002.md)

## Outcome

One fresh reference series produces either a valid four-teaser personalized
result with truthful `N` or an explicit non-success outcome, using exact scoped
search and the accepted best-effort group semantics.

## Requirements

- `REQ-SRCH-001`, `REQ-SRCH-002`, `REQ-SRCH-003`, `REQ-CAP-002`,
  `REQ-CAP-003`, `REQ-PERF-001`.
- Cross-cutting: `REQ-SEC-001`, `REQ-ARCH-001`.
- Registry: [.memory-bank/requirements.md](../requirements.md).

## Use Cases

- Select at most five highest-quality detections and search each independently.
- Search only compatible searchable commercial inventory for the token-bound СПА
  and operator-selected active `visit_date`.
- Assemble four unique valid teaser photos and the complete valid unique-photo
  union used for `N`.

## Acceptance Criteria

- The selected serving pipeline is pre-warmed and preserves its native detector,
  preprocessing and alignment path.
- Exact cosine search is filtered before comparison by pipeline revision, СПА
  and authoritative date; optional time windows require confirmed clock quality.
- Query-quality and calibrated reference threshold are mandatory gates;
  top-1/top-2 margin is absent.
- Detections remain independent, may repeat one physical person and do not use
  tracking, identity clustering or cross-pipeline linking.
- pHash only ranks threshold-valid matches. Teasers contain four unique
  `photo_id` values, while `N` counts the complete unique valid union.
- Controlled-attempt correctness rejects every unrelated teaser or result ID but
  does not require complete group-member coverage.
- Realtime requests are rate-limited; the server derives `spa_id` only from a
  stored `spa_client_token` hash, never trusts request-body `spa_id`, and never
  logs the token.

## Edge and Failure Behavior

- Missing active date prevents search and records diagnostic evidence.
- Search uses all currently `ready` compatible photos for the active СПА/date;
  while upload/processing continues, observing a partial current-day set is
  acceptable and does not require an ingest-group readiness gate.
- Fewer than four unique valid teaser photos is a non-success outcome.
- One photo matching multiple selected detections contributes to `N` once.
