# FT-007 — Correlated Attempt Evidence

**Epic:** [EP-003 — Explainable Diagnostics and Calibration](../epics/EP-003.md)

## Outcome

Every capture/search request admitted by the server, including non-success,
retains one core Attempt and correlated stage timeline. Client-only offline
attempt delivery and detailed evidence are best-effort without blocking the
participant flow, and gaps remain explicit.

## Requirements

- `REQ-DIAG-001`, `REQ-DIAG-002`, `REQ-PERF-001`.
- Cross-cutting: `REQ-SEC-001`, `REQ-DATA-001`, `REQ-ARCH-001`.
- Registry: [.memory-bank/requirements.md](../requirements.md).

## Use Cases

- Correlate browser and server activity by one attempt identifier.
- Inspect capture, network, singleton-slot acquisition/`busy`, inference,
  search, response, render and full QR visibility timestamps.
- Retain client-local markers for ready-series processing start, request-send
  start and response receipt.
- When collected, reproduce the applied release, pipeline, parameter, detection,
  candidate, teaser and `N` decision context from a redacted manifest.
- Open available capture-derived media without treating image content alone as
  developer-only.
- Read the latest retention outcome defined by the
  [canonical cleanup contract](../contracts/boundary-map.md).

## Acceptance Criteria

- Every request admitted by the server creates one core
  `attempt_id/correlation_id` before inference and retains outcome, issue tags
  and the PRD-defined stage timeline. Client-only offline attempt delivery is
  best-effort and may have no durable server record.
- An admitted zero-proposal metadata request creates the same core Attempt and
  explicit non-success outcome.
- Detailed evidence attaches best-effort. A terminal attempt without finalized
  evidence remains visible as `incomplete`.
- When present, evidence records versions, applied values, selected/repeated
  detections, candidate pools, selected teasers, `N`, camera/config metadata and
  QR event.
- Capture-derived reference images, normalized images and crops are ordinary
  media and may be logged, cached, stored or delivered without developer-only
  media authorization; none of those mechanisms or per-crop logging is
  required.
- The current no-selfie pilot does not invent a separate selfie artifact.
- Evidence ingestion is non-blocking, and any evidence gap remains observable.

## Edge and Failure Behavior

- Timeout, no-match and failures after server admission still create an attempt
  outcome. A client-only offline failure may exist only as a transient local
  notice/metadata event.
- Ordinary attempt/evidence data expires after 90 days.
- Promotion preserves only the curated PRD subset, not the whole ordinary
  evidence set or Promo screenshot.
- Evidence completeness does not require reference-frame upload or proof of
  occurrences missed by the local detector.

- A slow or failed attempt can be localized from its core timeline without
  forbidden log payloads; missing details are visibly `incomplete`.

- A client-only offline failure may remain absent from server Attempts without
  violating the best-effort contract.
