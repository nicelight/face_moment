# FT-007 — Correlated Attempt Evidence

**Epic:** [EP-003 — Explainable Diagnostics and Calibration](../epics/EP-003.md)

## Outcome

Every capture/search request admitted by the server, including non-success,
retains one core Attempt and correlated stage timeline. Client-only offline
attempt delivery and detailed evidence are best-effort without blocking the
participant flow, and gaps remain explicit.

## Requirements

- `REQ-DIAG-001`, `REQ-DIAG-002`, `REQ-PERF-001`.
- Cross-cutting: `REQ-REL-001`, `REQ-DATA-001`, `REQ-ARCH-001`.
- Registry: [.memory-bank/requirements.md](../requirements.md).

## Use Cases

- Correlate browser and server activity by one attempt identifier.
- Inspect capture, network, singleton-slot acquisition/`busy`, inference,
  search, response, render and full QR visibility timestamps.
- Retain client-local markers for ready-series processing start, request-send
  start and response receipt.
- When collected, reproduce the applied release, pipeline, parameter, detection,
  candidate, teaser and `N` decision context from a redacted manifest.
- Open available capture-derived media without treating image content alone as
  developer-only.
- Read the latest retention outcome defined by the
  [canonical cleanup contract](../contracts/boundary-map.md).

## Acceptance Criteria

### FT-007-AC-001 — Core Attempt and diagnostic timeline

- REQ: REQ-DIAG-001, REQ-PERF-001
- Observable criterion: Every server-admitted request, including zero-proposal
  and other non-success outcomes, persists one core
  `attempt_id/correlation_id` before inference with outcome, issue tags and a
  stage timeline containing client-local ready-series processing start,
  request-send start and response receipt plus the server/display stages needed
  to localize latency.
- Verification: Admit success, zero-proposal, busy/deadline and technical-
  failure fixtures and inspect persistence plus monotonic marker ordering.

### FT-007-AC-002 — Best-effort reproducible evidence

- REQ: REQ-DIAG-002
- Observable criterion: Detailed evidence never blocks core Attempt completion;
  when present it exposes release/pipeline/applied values, selected and repeated
  detections, candidate pools, teasers, `N`, camera/config metadata and QR event,
  while failed/absent finalization leaves the terminal Attempt visibly
  `incomplete` with an explicit gap.
- Verification: Run complete, partial and failed-finalization evidence paths and
  compare participant outcome, manifest content and completeness state.

### FT-007-AC-003 — Capture-media classification and no-selfie scope

- REQ: REQ-DIAG-002
- Observable criterion: Capture-derived reference images, normalized images and
  crops are not developer-only solely because of image content and may be
  logged, cached, stored or delivered behind applicable boundaries; none of
  those mechanisms, per-crop logging or a selfie artifact is required in the
  current no-selfie pilot.
- Verification: Check representative authorization/delivery decisions and
  artifact inventory without requiring capture persistence or creating a selfie
  record.

### FT-007-AC-004 — Evidence retention and promoted subset

- REQ: REQ-DATA-001, REQ-DIAG-002
- Observable criterion: Ordinary Attempts/evidence and persisted capture media
  expire after 90 days; promotion preserves only the curated PRD subset, not the
  entire bundle or Promo screenshot; authorized users can observe the latest
  cleanup cutoffs, confirmed deleted/preserved counts and outcome/error.
- Verification: Apply retention to ordinary, incomplete and promoted fixtures,
  inspect retained/deleted artifacts and the latest rerunnable cleanup result.

### FT-007-AC-005 — Client-only offline best effort

- REQ: REQ-DIAG-001, REQ-REL-001
- Observable criterion: A client-only offline failure may produce only a
  transient notice/metadata event and no durable server Attempt, while any
  failure after server admission still retains the core Attempt outcome.
- Verification: Disconnect before and after admission and compare server
  Attempts, client-local metadata expiry and observable outcome.

## Edge and Failure Behavior

- Timeout, no-match and failures after server admission still create an attempt
  outcome. A client-only offline failure may exist only as a transient local
  notice/metadata event. Covered by `FT-007-AC-001` and `FT-007-AC-005`.
- Ordinary attempt/evidence data expires after 90 days. Covered by
  `FT-007-AC-004`.
- Promotion preserves only the curated PRD subset, not the whole ordinary
  evidence set or Promo screenshot. Covered by `FT-007-AC-004`.
- Evidence completeness does not require reference-frame upload or proof of
  occurrences missed by the local detector. Covered by `FT-007-AC-002` and
  `FT-007-AC-003`.

- `FT-007-AC-001..005`, preserving PRD AC-05, AC-10, AC-13 and AC-22.

  violating the best-effort contract.

## SDD Design Gate

markers have direct canonical routes. Revalidated at Planning Revision `4`:
the manifest's client timing/identity fields feed correlation without changing
the server-admission rule, core Attempt ownership or best-effort evidence
lifecycle.
