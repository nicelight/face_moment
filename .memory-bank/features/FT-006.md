# FT-006 — QR Phone Continuation

**Epic:** [EP-002 — Automatic Promo and QR Continuation](../epics/EP-002.md)

## Outcome

A participant scans the display QR and immediately continues the same
personalized result on a phone without a new selfie, while independent expiry
rules prevent stale personal data disclosure.

## Requirements

- `REQ-UX-002`, `REQ-UX-003`.
- Cross-cutting: `REQ-SEC-001`, `REQ-ARCH-001`.
- Registry: [.memory-bank/requirements.md](../requirements.md).

## Use Cases

- Open a valid issued Promo/search session from the display QR.
- View the same session's СПА, authoritative date, an available teaser when
  present and issued `N`.
- Use `Перейти к покупке` to navigate to the separately delivered main Face
  Moment page.
- Handle first-open and session-wide browser-idle expiry without revealing
  prior result data.

## Acceptance Criteria

- Continuation requires no participant login step or new selfie in the immediate
  QR flow.
- Phone content is bound to the same СПА, `visit_date`, teaser set and
  `session_result_photo_ids`/`N` as the displayed result. Soft delete does not
  invalidate the issued session. If media is later hard-purged, the missing item
  is skipped and issued `N` is not recalculated.
- A QR scan may open or reuse one session-wide browser access context for 30
  minutes from `qr_issued_at`; no independent per-device grant is created.
- After a valid first open, the shared browser context expires after 60 minutes
  without explicit participant activity on any opened phone.
- Display duration, success cooldown, first-open TTL and browser-idle TTL remain
  independent.
- Expiry redirects to the main Face Moment page without teaser, `N` or other
  personalized session data.
- Public continuation uses HTTPS and rate limiting while PostgreSQL, object
  storage and internal service ports remain private.

## Edge and Failure Behavior

- Expiring the display does not implicitly expire the personalized session.
- Missing hard-purged media does not expire or rebuild the personalized session.
- A late first open and an idle shared browser context both lose personalized
  access.
- The pilot verifies navigation and isolation, not implementation of the target
  purchase/selfie-search page.
