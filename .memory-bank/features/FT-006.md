# FT-006 — QR Phone Continuation

**Epic:** [EP-002 — Automatic Promo and QR Continuation](../epics/EP-002.md)

## Outcome

A participant scans the display QR and immediately continues the same
personalized result on a phone without a new selfie, while independent expiry
rules prevent stale personal data disclosure.

## Requirements

- `REQ-UX-002`, `REQ-UX-003`.
- Cross-cutting: `REQ-SEC-001`, `REQ-ARCH-001`.
- Registry: [.memory-bank/requirements.md](../requirements.md).

## Use Cases

- Open a valid issued Promo/search session from the display QR.
- View the same session's СПА, authoritative date, an available teaser when
  present and issued `N`.
- Use `Перейти к покупке` to navigate to the separately delivered main Face
  Moment page.
- Handle first-open and session-wide browser-idle expiry without revealing
  prior result data.

## Acceptance Criteria

### FT-006-AC-001 — Same-session phone continuation

- REQ: REQ-UX-002
- Observable criterion: A valid QR opens the displayed Promo/search session
  without participant login or a new selfie and shows the same СПА,
  authoritative `visit_date`, an available session teaser, issued `N` and the
  purchase-navigation CTA. Soft delete does not invalidate it; hard-purged
  media is skipped without session rebuild or `N` recalculation.
- Verification: Compare display/session/phone identifiers and content before
  and after soft delete and hard purge, including CTA navigation.

### FT-006-AC-002 — Session-wide access lifetime

- REQ: REQ-UX-003
- Observable criterion: Every scan before 30 minutes from `qr_issued_at` opens
  or reuses one session-wide browser access context without per-device grants;
  every valid repeated scan advances its shared `browser_last_seen_at`, and
  explicit activity on any opened phone advances the same one 60-minute idle
  lifetime.
- Verification: Exercise repeated scans from multiple phones around the first-
  open boundary and shared activity/idle boundary while inspecting access
  state cardinality and timestamps.

### FT-006-AC-003 — Independent expiry and data isolation

- REQ: REQ-UX-003
- Observable criterion: Display duration, success cooldown, QR first-open TTL
  and browser idle TTL remain independent; late first-open or shared-idle expiry
  removes personalized access and redirects to the separate main Face Moment
  page without teaser, `N` or other expired-session data.
- Verification: Drive each timer independently and inspect redirect response,
  rendered state, URL/referrer/cache behavior and subsequent session reads for
  leakage.

### FT-006-AC-004 — Protected public continuation boundary

- REQ: REQ-SEC-001
- Observable criterion: Every public phone-continuation route applies a
  positive deployment-configured public-request rate limit; excess requests
  receive `429` without credential or personalized-data disclosure.
- Verification: Run exact-route integration checks for configured rate-limit
  enforcement, forwarded client separation, `429`, redaction and protected
  response behavior.

### FT-006-AC-005 — Pilot topology and external navigation acceptance

- REQ: REQ-SEC-001, REQ-ARCH-001, REQ-UX-002
- Observable criterion: The authorized pilot exposes phone continuation only
  through HTTPS while PostgreSQL, object storage and internal services stay
  private, and its purchase CTA reaches the configured external Face Moment
  target without claiming implementation of that separate page.
- Verification: Inspect the deployed public/private topology and redacted edge
  receipts, then confirm the CTA reaches only the configured absolute HTTPS
  target without personalized parameters.

## Edge and Failure Behavior

- Expiring the display does not implicitly expire the personalized session.
  Covered by `FT-006-AC-003`.
- Missing hard-purged media does not expire or rebuild the personalized session.
  Covered by `FT-006-AC-001`.
- A late first open and an idle shared browser context both lose personalized
  access. Covered by `FT-006-AC-002` and `FT-006-AC-003`.
- The pilot verifies navigation and isolation, not implementation of the target
  purchase/selfie-search page.
  - Disposition: out_of_scope
  - Source: PRD `Non-goals`, `FR-UX-05` and `FR-UX-10`.
  - Change route: /write-prd

## Clarifications

### 2026-08-24 — Task-plan review reconciliation

- A valid repeated scan before the first-open deadline advances the same shared
  `browser_last_seen_at`; explicit in-page activity advances that field as a
  separate operation, while passive reads and media loads do not.
- Observable multi-phone lifetime proof belongs with the complete phone
  continuation flow; persistence/migration work remains a separate technical
  prerequisite and does not own `FT-006-AC-002` by itself.
- Public-route rate-limit implementation and `429` proof are distinct from the
  final authorized pilot topology/CTA observation, so accepted AC-004 was
  narrowed to implementation behavior and AC-005 was added for production
  acceptance. No product target or canonical runtime behavior changed.
- Real-browser expiry/isolation proof closes the implementation continuation
  outcome with deterministic fixtures. The physical same-session phone join is
  post-deployment pilot validation and is deferred until the server, display
  and authorized phone environment exist; final production acceptance does not
  repeat the deterministic sibling claims.

## SDD Design Gate

Complete. The subject-based QR contract fixes the public exchange, protected
phone read, shared activity and redirect surface; the existing Promo domain,
lifecycle and client-realtime verification specs fix owner state, independent
timers, missing-media behavior and the post-display phone-read join. No
feature-owned spec hub is needed.
