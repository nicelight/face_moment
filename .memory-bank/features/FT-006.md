# FT-006 — QR Phone Continuation

**Epic:** [EP-002 — Automatic Promo and QR Continuation](../epics/EP-002.md)

## Outcome

A participant scans the display QR and immediately continues the same
personalized result on a phone without a new selfie, while independent expiry
rules prevent stale personal data disclosure.

## Requirements

- `REQ-UX-002`, `REQ-UX-003`.
- Cross-cutting: `REQ-SEC-001`, `REQ-ARCH-001`.
- Registry: [.memory-bank/requirements.md](../requirements.md).

## Use Cases

- Open a valid issued Promo/search session from the display QR.
- View the same session's СПА, authoritative date, an available teaser when
  present and issued `N`.
- Use `Перейти к покупке` to navigate to the separately delivered main Face
  Moment page.
- Handle first-open and session-wide browser-idle expiry without revealing
  prior result data.

## Acceptance Criteria

### FT-006-AC-001 — Same-session phone continuation

- REQ: REQ-UX-002
- Observable criterion: A valid QR opens the displayed Promo/search session
  without participant login or a new selfie and shows the same СПА,
  authoritative `visit_date`, an available session teaser, issued `N` and the
  purchase-navigation CTA. Soft delete does not invalidate it; hard-purged
  media is skipped without session rebuild or `N` recalculation.
- Verification: Compare display/session/phone identifiers and content before
  and after soft delete and hard purge, including CTA navigation.

### FT-006-AC-002 — Session-wide access lifetime

- REQ: REQ-UX-003
- Observable criterion: Every scan before 30 minutes from `qr_issued_at` opens
  or reuses one session-wide browser access context without per-device grants;
  after first open, explicit activity on any opened phone shares one 60-minute
  idle lifetime.
- Verification: Exercise repeated scans from multiple phones around the first-
  open boundary and shared activity/idle boundary while inspecting access
  state cardinality and timestamps.

### FT-006-AC-003 — Independent expiry and data isolation

- REQ: REQ-UX-003
- Observable criterion: Display duration, success cooldown, QR first-open TTL
  and browser idle TTL remain independent; late first-open or shared-idle expiry
  removes personalized access and redirects to the separate main Face Moment
  page without teaser, `N` or other expired-session data.
- Verification: Drive each timer independently and inspect redirect response,
  rendered state, URL/referrer/cache behavior and subsequent session reads for
  leakage.

### FT-006-AC-004 — Protected public continuation boundary

- REQ: REQ-SEC-001, REQ-UX-002
- Observable criterion: Phone continuation uses HTTPS and public-request rate
  limiting while PostgreSQL, object storage and internal services stay private;
  the pilot verifies the purchase-page navigation boundary without claiming
  implementation of that separate page.
- Verification: Run authorization/rate-limit/topology checks and confirm the CTA
  reaches the configured external target without accepting its implementation.

## Edge and Failure Behavior

- Expiring the display does not implicitly expire the personalized session.
  Covered by `FT-006-AC-003`.
- Missing hard-purged media does not expire or rebuild the personalized session.
  Covered by `FT-006-AC-001`.
- A late first open and an idle shared browser context both lose personalized
  access. Covered by `FT-006-AC-002` and `FT-006-AC-003`.
- The pilot verifies navigation and isolation, not implementation of the target
  purchase/selfie-search page.
  - Disposition: out_of_scope
  - Source: PRD `Non-goals`, `FR-UX-05` and `FR-UX-10`.
  - Change route: /write-prd
