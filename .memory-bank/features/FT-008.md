# FT-008 — Role-scoped Attempts

**Epic:** [EP-003 — Explainable Diagnostics and Calibration](../epics/EP-003.md)

## Outcome

An operator can find a slow, failed or suspicious attempt and inspect its
sanitized outcome and timing, while an authorized developer can open the
role-restricted detail through the project application.

## Requirements

- `REQ-DIAG-003`.
- Cross-cutting: `REQ-DIAG-001`, `REQ-DATA-001`, `REQ-ARCH-001`.
- Registry: [.memory-bank/requirements.md](../requirements.md).

## Use Cases

- Filter Attempts by time, status, release, pipeline, latency and issue tags.
- Open the combined browser/server stage timeline for one attempt.
- See client-local ready-series processing start, request-send start and
  response receipt in the diagnostic timeline.
- Present sanitized or role-restricted attempt detail according to operator or
  developer authority.
- Navigate from developer attempt detail to its authorized artifacts,
  annotations, Calibration and related Log Explorer context owned by
  [FT-009](FT-009.md).

## Acceptance Criteria

### FT-008-AC-001 — Searchable correlated Attempts

- REQ: REQ-DIAG-001, REQ-DIAG-003
- Observable criterion: Attempts filters by time, status, release, pipeline,
  latency and issue tags and opens one correlated browser/server timeline with
  the three required client-local markers and related-detail navigation.
- Verification: Seed representative attempts and exercise every filter,
  combined timeline marker and attempt-detail route.

### FT-008-AC-002 — Sanitized operator view

- REQ: REQ-DIAG-003
- Observable criterion: An operator can inspect only outcome, stage timeline,
  latency and issue tags; participant names, annotations, detailed logs and
  Calibration remain unavailable.
- Verification: Run list/detail/direct-link authorization checks as operator and
  inspect response/rendered fields for the exact sanitized projection.

### FT-008-AC-003 — Authorized developer investigation

- REQ: REQ-DIAG-003
- Observable criterion: An authorized developer can open allowed names,
  annotations, detailed logs, Calibration and artifact navigation; capture-
  derived media is not denied solely because it contains image content, and
  structured-log navigation does not absorb the separate FT-009 search outcome.
- Verification: Exercise developer detail/artifact/log/Calibration links and
  confirm ownership and data-class-specific authorization at each boundary.

### FT-008-AC-004 — Photographer and unauthorized isolation

- REQ: REQ-DIAG-003
- Observable criterion: A photographer remains limited to owned uploaded-photo
  state, and direct links, stale UI state or role changes cannot disclose any
  diagnostic detail beyond current authority.
- Verification: Attempt list/detail/artifact access as photographer,
  unauthenticated user and downgraded principal, including previously captured
  URLs.

### FT-008-AC-005 — Truthful missing and expired detail

- REQ: REQ-DIAG-003, REQ-DATA-001
- Observable criterion: Missing evidence is visibly incomplete rather than
  presented as a complete history, and expired ordinary attempt data cannot be
  recovered through stale navigation.
- Verification: Open incomplete and retention-expired fixtures through current
  and stale routes and inspect user-visible state plus response authorization.

## Edge and Failure Behavior

- Missing evidence remains visible rather than being presented as a complete
  attempt history. Covered by `FT-008-AC-005`.
- Expired ordinary attempt data cannot be recovered through stale navigation.
  Covered by `FT-008-AC-005`.
- Role changes or direct-link access never widen the PRD authorization matrix.
  Covered by `FT-008-AC-002`, `FT-008-AC-003` and `FT-008-AC-004`.
