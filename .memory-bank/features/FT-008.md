# FT-008 — Role-scoped Attempts

**Epic:** [EP-003 — Explainable Diagnostics and Calibration](../epics/EP-003.md)

## Outcome

An operator or authorized developer can find one Attempt and investigate its
available state, stages, durations and evidence through the project
application, with the projection restricted by role and missing data shown
truthfully.

## Requirements

- `REQ-DIAG-003`.
- Cross-cutting: `REQ-DIAG-001`, `REQ-DATA-001`, `REQ-ARCH-001`.
- Registry: [.memory-bank/requirements.md](../requirements.md).

## Use Cases

- Find an Attempt by exact `attempt_id` or `correlation_id`, or narrow the table
  by time and state.
- Open the tabular state, server stages and durations for one Attempt.
- See client-local ready-series processing start, request-send start and
  response receipt when those markers are available.
- Inspect already collected `DiagnosticEvidence` without requiring FT-008 to
  create additional evidence, artifacts or specialized diagnostic entities.
- Present sanitized or developer-authorized detail according to current role.

## Acceptance Criteria

### FT-008-AC-001 — Exact correlated Attempt investigation

- REQ: REQ-DIAG-001, REQ-DIAG-003
- Observable criterion: Attempts supports exact `attempt_id`/`correlation_id`
  lookup plus time/state filters and opens one row/detail with state, outcome,
  server stages/durations, available client markers and available
  `DiagnosticEvidence`.
- Verification: Seed representative attempts and exercise both exact IDs,
  time/state filters and every tabular/detail field.

### FT-008-AC-002 — Sanitized operator view

- REQ: REQ-DIAG-003
- Observable criterion: An operator can inspect only outcome, stage timeline,
  latency and issue tags; developer-only evidence, participant names,
  annotations, server events and Calibration remain unavailable.
- Verification: Run list/detail/direct-link authorization checks as operator and
  inspect response/rendered fields for the exact sanitized projection.

### FT-008-AC-003 — Authorized developer investigation

- REQ: REQ-DIAG-003
- Observable criterion: An authorized developer can inspect the existing
  role-allowed Attempt and `DiagnosticEvidence` fields. FT-008 does not require
  annotation, Calibration, new artifact or server-event navigation and does not
  absorb the separate FT-009 outcome.
- Verification: Exercise developer detail with complete, partial and absent
  evidence, then confirm that unrelated diagnostic-feature data is neither
  required nor silently projected into FT-008.

### FT-008-AC-004 — Photographer and unauthorized isolation

- REQ: REQ-DIAG-003
- Observable criterion: A photographer remains limited to owned uploaded-photo
  state, and direct links, stale UI state or role changes cannot disclose any
  diagnostic detail beyond current authority.
- Verification: Attempt list/detail/artifact access as photographer,
  unauthenticated user and downgraded principal, including previously captured
  URLs.

### FT-008-AC-005 — Truthful missing, expired and removed detail

- REQ: REQ-DIAG-003, REQ-DATA-001
- Observable criterion: For an existing Attempt, unavailable evidence is shown
  truthfully as `incomplete`, `expired` or `removed` rather than as a complete
  history; stale navigation cannot recover expired or removed content.
- Verification: Open incomplete, retention-expired and explicitly removed
  evidence fixtures through current and stale routes and verify the distinct
  visible state plus absence of deleted content.

## Edge and Failure Behavior

- Missing, expired and removed evidence states remain visibly distinct, and
  expired or removed content cannot be recovered through stale navigation.
  Covered by `FT-008-AC-005`.
- Role changes or direct-link access never widen the PRD authorization matrix.
  Covered by `FT-008-AC-002`, `FT-008-AC-003` and `FT-008-AC-004`.
