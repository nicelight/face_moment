# FT-008 — Role-scoped Attempts

**Epic:** [EP-003 — Explainable Diagnostics and Calibration](../epics/EP-003.md)

## Outcome

An operator can find a slow, failed or suspicious attempt and inspect its
sanitized outcome and timing, while an authorized developer can open the same
attempt's protected diagnostic detail through the project application.

## Requirements

- `REQ-DIAG-003`.
- Cross-cutting: `REQ-DATA-001`, `REQ-ARCH-001`.
- Registry: [.memory-bank/requirements.md](../requirements.md).

## Use Cases

- Filter Attempts by time, status, release, pipeline, latency and issue tags.
- Open the combined browser/server stage timeline for one attempt.
- Present sanitized or protected attempt detail according to operator or
  developer authority.
- Navigate from developer attempt detail to its authorized artifacts,
  annotations, Calibration and related Log Explorer context owned by
  [FT-009](FT-009.md).

## Acceptance Criteria

- Attempts supports all PRD-required list filters and opens one correlated
  timeline/detail context.
- Operator access is limited to outcome, stage timeline, latency and issue tags.
- Developer access may include protected images/crops, participant names,
  annotations, detailed diagnostic evidence and Calibration navigation.
- Attempt detail preserves navigation to related structured logs without owning
  the Log Explorer search outcome.
- Photographer access remains limited to owned uploaded-photo state and excludes
  diagnostic pages.
- Unauthorized navigation cannot reveal protected artifact links or detail.

## Edge and Failure Behavior

- Missing evidence remains visible rather than being presented as a complete
  attempt history.
- Expired ordinary attempt data cannot be recovered through stale navigation.
- Role changes or direct-link access never widen the PRD authorization matrix.
