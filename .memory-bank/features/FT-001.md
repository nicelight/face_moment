# FT-001 — Independent Photo Admission

**Epic:** [EP-001 — Fresh Searchable Inventory](../epics/EP-001.md)

## Outcome

An authenticated photographer can select one СПА and authoritative working date,
upload ready JPEGs independently, and understand each file's admission outcome
without a group confirmation step.

## Requirements

- `REQ-ING-001`, `REQ-ING-002`, `REQ-ING-003`.
- Cross-cutting: `REQ-SEC-001`, `REQ-ARCH-001`.
- Registry: [.memory-bank/requirements.md](../requirements.md).

## Use Cases

- Select СПА plus authoritative `visit_date` for subsequent uploads.
- Upload multiple ready JPEG files through the authenticated HTTPS application.
- Observe accepted, rejected, warning or duplicate outcome per completed file.
- Observe each accepted Photo enter background processing independently.

## Acceptance Criteria

### FT-001-AC-001 — Independent admission outcomes

- REQ: REQ-ING-001, REQ-ING-002
- Observable criterion: An authenticated photographer selects one СПА and
  authoritative `visit_date`; every completed ready-JPEG upload independently
  reports accepted, rejected or duplicate, while invalid/undecodable input is
  rejected and mixed EXIF dates never rewrite or regroup the selected scope.
- Verification: Exercise valid, invalid, undecodable and mixed-EXIF uploads and
  assert the per-file UI/API outcome and persisted authoritative date.

### FT-001-AC-002 — Duplicate exclusion

- REQ: REQ-ING-003
- Observable criterion: Uniqueness is enforced by
  `(spa_id, visit_date, checksum_sha256)`; a duplicate candidate object is
  deleted and reported without creating another `photo_id`, pipeline state,
  searchable result, teaser candidate or contribution to `N`.
- Verification: Re-upload the same JPEG in the same СПА/date, including a
  concurrent duplicate attempt, and compare object, Photo and downstream-state
  counts before and after.

### FT-001-AC-003 — Atomic accepted Photo publication

- REQ: REQ-ING-003
- Observable criterion: For each valid unique object, one short PostgreSQL
  transaction publishes Photo, server-side `accepted_at` and its serving-
  pipeline `pending` state together; no partially admitted database state is
  observable.
- Verification: Inspect transaction-boundary integration evidence for success
  and injected rollback, asserting either the complete triplet or no database
  admission.

### FT-001-AC-004 — Authenticated rate-limited private ingest boundary

- REQ: REQ-ING-001, REQ-SEC-001, REQ-ARCH-001
- Observable criterion: Direct authenticated HTTPS upload is the only pilot
  ingest path; its public uploader requests are rate-limited, with excess rate
  rejected through standard HTTP `429`, and the photographer flow exposes
  neither PostgreSQL, object storage nor internal service ports.
- Verification: Run application-boundary authorization, rate-limit and topology
  checks, including unauthenticated rejection, successful requests below the
  configured limit, `429` above it and absence of direct internal-service
  browser access.

### FT-001-AC-005 — Accepted pre-commit crash recovery

- REQ: REQ-ING-003, REQ-ARCH-001
- Observable criterion: A crash after private-object upload but before the
  PostgreSQL commit creates no Photo or pipeline state; a possible private
  orphan remains inaccessible and a photographer re-upload can complete normal
  admission.
- Verification: Inject failure immediately before commit, confirm no database
  admission or exposed media, then re-upload the JPEG successfully.

## Edge and Failure Behavior

- Rejects and duplicates never enter metric population. Covered by
  `FT-001-AC-001` and `FT-001-AC-002`.
- Repeated upload is idempotent within the PRD duplicate scope. Covered by
  `FT-001-AC-002`.
- A crash after private-object upload but before the per-photo DB commit may
  leave one orphan and lose that admission; photographer re-upload is the
  accepted recovery. Covered by `FT-001-AC-005`.
- Uploader requests above the applicable rate limit return standard HTTP `429`
  without weakening the authenticated HTTPS/private-service boundary. Covered
  by `FT-001-AC-004`.
- Yandex Disk, RAW, OAuth, Telegram and EXIF-based auto-split remain post-pilot.
  - Disposition: out_of_scope
  - Source: PRD `Non-goals` and `FR-ING-01..02`.
  - Change route: /write-prd
