# FT-011 — Explainable Calibration

**Epic:** [EP-003 — Explainable Diagnostics and Calibration](../epics/EP-003.md)

## Outcome

An authorized developer can test-only compare the named SFace and Buffalo M
pipeline revisions and parameter sets on one immutable selected dataset of
existing Photo original JPEG bytes and applicable annotated Attempts, inspect
explainable threshold and one-dimensional input-quality recommendations, and
then decide separately whether to apply a serving-setting change manually.

## Requirements

- `REQ-CAL-001`, `REQ-CAL-002`, `REQ-CAL-003`.
- Cross-cutting: `REQ-DATA-001`, `REQ-ARCH-001`.
- Registry: [.memory-bank/requirements.md](../requirements.md).

## Use Cases

- Compare SFace and Buffalo M revisions on the same immutable selected dataset
  of existing Photo original JPEG bytes and applicable annotated Attempts,
  without reupload.
- Inspect `Best face match`, `Balance` and `Minimum missed faces` threshold
  profiles and drill down to contributing attempts.
- Analyze face size, detection confidence, blur, brightness and pose gates one at
  a time.
- Compare before/after release or parameter-set results and manually apply a
  selected serving change through the later audited boundary.
- Run Calibration on the shared background worker and manually rerun an
  interrupted analysis after photo processing has resumed.

## Acceptance Criteria

### FT-011-AC-001 — Explainable threshold profiles

- REQ: REQ-CAL-001
- Observable criterion: Calibration compares the named SFace and Buffalo M
  native pipeline paths, without an arbitrary plugin/model registry, and
  presents `Best face match`, `Balance` and `Minimum missed faces`; every
  recommendation shows proposed threshold, correct/false/missed counts,
  precision, recall, annotated sample size and contributing-Attempt drill-down.
  The first and third profiles obey their PRD tie-breaks. `Balance` maximizes
  aggregate
  `F1 = 2 * correct / (2 * correct + false + missed)`; equal F1 is resolved by
  fewer `false`, then fewer `missed`, then the higher (stricter) threshold.
- Verification: Calculate all profiles over a fixed annotated sample, compare
  metrics/drill-down with an independent calculation and assert the accepted
  `Balance` objective and complete tie-break order for each named pipeline
  revision without treating either pipeline as a registry plugin.

### FT-011-AC-002 — One-dimensional quality recommendations

- REQ: REQ-CAL-002
- Observable criterion: Face size, detection confidence, blur, brightness and
  pose are analysed one at a time; each output shows current/proposed value,
  sample size, kept/rejected detections and expected correct/false/missed
  changes, without joint multidimensional optimization.
- Verification: Vary each gate independently on one annotated fixture set and
  assert output fields plus unchanged values for all other gates.

### FT-011-AC-003 — Reproducible before/after comparison

- REQ: REQ-CAL-002
- Observable criterion: A Calibration comparison snapshots one immutable
  selected dataset of existing Photo original JPEG bytes and applicable
  annotated Attempts. Every selected SFace or Buffalo M pipeline revision
  receives exactly those same source bytes and selection without reupload.
  Stored releases, parameter sets, outcomes and annotations remain separate by
  run, input dataset and pipeline revision for before/after comparison and
  contributing-Attempt inspection, without a separate experimentation platform.
- Verification: Create one selected dataset from existing Photo original JPEG
  bytes and applicable annotated Attempts; evaluate two selected
  release/configuration or pipeline-revision fixtures from that unchanged
  dataset without reupload; reconcile each separate result with its stored
  input identity, revision and underlying annotated Attempts.

### FT-011-AC-004 — Manual-only serving change

- REQ: REQ-CAL-002
- Observable criterion: Dataset selection and Calibration evaluation are
  test-only and never mutate serving settings or serving revision automatically;
  any accepted change requires a separate explicit developer action through the
  serving-control boundary.
- Verification: Create and inspect separate Calibration results while asserting
  unchanged serving state, then verify only the separately authorized command
  can change it.

### FT-011-AC-005 — Shared-worker interruption recovery

- REQ: REQ-CAL-003, REQ-ARCH-001
- Observable criterion: Calibration may delay photo processing on the shared
  worker during debugging; worker restart makes the run visibly `failed` or
  `interrupted`, resumes queued Photo work and leaves rerun as a manual action
  without preemption, priority scheduling or a separate Calibration worker.
- Verification: Restart during Calibration with queued Photo work and inspect
  run terminal state, Photo processing resumption and absence of automatic
  replacement execution.

### FT-011-AC-006 — Honest unavailable recommendation

- REQ: REQ-CAL-001, REQ-CAL-002
- Observable criterion: When the accepted metrics are undefined for every
  candidate, Calibration shows selected/applicable sample size, produces no
  proposal and cannot trigger an automatic change.
- Verification: Run calculations with undefined accepted metrics, then inspect
  the sample warning, absent proposal and unchanged serving state.

### FT-011-AC-007 — Ordinary Calibration run retention

- REQ: REQ-DATA-001
- Observable criterion: Terminal ordinary Calibration runs expire with the
  90-day diagnostics cutoff without changing the existing public cleanup
  result; equal/new terminal and active runs remain, and rerun is safe.
- Verification: Apply the fixed cutoff to old/equal/new terminal and active
  runs, repeat cleanup, and inspect exact surviving state plus the unchanged
  latest-result shape.

### FT-011-AC-008 — Promoted Calibration case lifecycle

- REQ: REQ-DATA-001
- Observable criterion: A separately confirmed developer action promotes only
  the selected curated PRD subset; ordinary cleanup preserves it until a
  separately confirmed idempotent whole-subset deletion.
- Verification: Promote selected/unselected disposable evidence, apply ordinary
  cleanup, then explicitly delete and repeat deletion while inspecting exact
  retained/removed state and excluded payloads.

## Edge and Failure Behavior

- Undefined recommendation metrics remain visible with sample size and cannot
  be hidden by an automatic serving change. Covered by `FT-011-AC-004` and
  `FT-011-AC-006`.
- Capture-window, frame-interval, group-selection, CPU/thread and UI/QR timing
  tuning remain outside the first Calibration scope.
  - Disposition: out_of_scope
  - Source: PRD `Non-goals` and `FR-DEV-08`.
  - Change route: /write-prd
- Promoted cases retain only the curated PRD subset until explicit deletion.
  Covered by `FT-011-AC-008`.
- No preemption, priority scheduler, automatic Calibration recovery or separate
  Calibration worker is required; the developer starts a replacement run.
  Covered by `FT-011-AC-005`.
- Calibration comparison reuses selected existing Photo original JPEG bytes and
  applicable annotated Attempts without reupload; it does not mutate serving
  state or add an arbitrary plugin/model registry. Covered by
  `FT-011-AC-001`, `FT-011-AC-003` and `FT-011-AC-004`.

## Clarifications

### 2026-08-01 — Deterministic `Balance` objective

- Operator answer: maximize aggregate
  `F1 = 2 * correct / (2 * correct + false + missed)`.
- Deterministic tie-break order: fewer `false`, then fewer `missed`, then the
  higher (stricter) threshold.
- Consequence: `FT-011-AC-001` and its verification now have a deterministic
  pass/fail rule. At that acceptance, annotation semantics, sample selection,
  the other threshold profiles, quality-gate analysis and manual-only serving
  application were unchanged; the 2026-08-14 clarification supersedes the
  sample-selection statement.
- Design impact: reconciled in the canonical
  [.memory-bank/testing/calibration.md](../testing/calibration.md) verification
  contract; behavior-spec refresh is not required because FT-011 has no linked
  behavior JSON.

### 2026-08-14 — Reusable immutable comparison dataset

- Operator answer: Calibration comparison is test-only. It reuses one immutable
  selected dataset without reupload: existing Photo original JPEG bytes plus
  applicable annotated Attempts. Every selected pipeline revision receives the
  same source bytes and selection; results remain separate by run, input dataset
  and pipeline revision and never mutate serving state.
- The current MVP comparison scope remains the named SFace and Buffalo M native
  paths; no arbitrary plugin/model registry is introduced.
- Consequence: `FT-011-AC-001`, `FT-011-AC-003`, `FT-011-AC-004` and their
  verification now set the durable test-only dataset-reuse boundary.
- Design impact: reconciled in the canonical Calibration data and verification
  contracts; behavior-spec refresh is not required because FT-011 has no linked
  behavior JSON.
