# FT-015 — Скачивание выбранных бесплатных фотографий

**Epic:** [EP-004](../epics/EP-004.md): публичный поиск и выбранные originals.

## Outcome

Посетитель скачивает выбранные бесплатные originals без оплаты и регистрации.

## Requirements

`REQ-PUB-005`, `REQ-PUB-007`, `REQ-PUB-008`. Registry: [requirements](../requirements.md).

## Acceptance Criteria

### FT-015-AC-001 — Free order HTTP without payment

- REQ: REQ-PUB-005, REQ-PUB-008
- Observable criterion: Public POST/read order consumes frozen core for selected free-venue personal and permitted common photos without mandatory email/payment. Owner reads status and ready link; forged paid/current-result/foreign profile input cannot obtain free originals. Browser interaction is AC-002, archive generation AC-004, bearer delivery AC-003.
- Verification: Actual backend HTTP/repository join, free venue/common at paid venue, invalid and foreign scope, no provider invocation/private keys; core snapshot/idempotence proof stays TASK-132.

### FT-015-AC-002 — Free browser download and preparation feedback

- REQ: REQ-PUB-005, REQ-PUB-007
- Observable criterion: «Скачать» on free-only selection requests one archive without receipt email/payment-method form, shows retry-in-30-seconds instruction while preparing, renders failure and ready download link. Generation/admin-mail outcome is AC-004. Future support-button local selfie retrieval отсутствует.
- Verification: Actual served browser/backend flow with ready/preparing/failed states, no payment navigation or email form; unit checks support browser proof.

### FT-015-AC-003 — Three-day private bearer delivery

- REQ: REQ-PUB-007, REQ-PUB-008
- Observable criterion: Ready free archive streams through signed bearer independently of cookie/device until strictly ready+3 days. Invalid token/unentitled/missing archive denies access; direct private originals stay unavailable. Missing/deleted archive shows safe manual-support error without preservation guarantee. ZIP composition belongs AC-004.
- Verification: Real route/private-store join, no-cookie second client, boundary clock, forged HMAC, stored pending/canceled/succeeded paid entitlement and anonymous original/store denial; provider transition belongs FT-016.

### FT-015-AC-004 — Bounded ZIP runtime, recovery and failure notification

- REQ: REQ-PUB-007
- Observable criterion: Backend executor prepares only frozen selected originals into private ZIP, publishes ready only after completion, recovers preparing after restart without shifting saved ready_at. Missing originals/build error yields failed and automatic admin-mail attempt to sergiosandroid2@gmail.com; mail failure preserves visible archive failure, no payment initiated. No separate job table/shared Photo worker or guaranteed retention.
- Verification: Actual backend startup executor, disposable DB/private-store ZIP members, blocked IO responsiveness, interrupted/restarted generation, failure and configured mail adapter with fake transport; no real email/payment.
