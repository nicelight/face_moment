# FT-009 — Minimal Server Events

**Epic:** [EP-003 — Explainable Diagnostics and Calibration](../epics/EP-003.md)

## Outcome

An authorized developer can inspect recent important redacted server events in
one minimal web page and navigate from an event with a known Attempt to FT-008
without impact on the participant-critical flow.

## Requirements

- `REQ-LOG-001`.
- Cross-cutting: `REQ-DATA-001`, `REQ-ARCH-001`.
- Registry: [.memory-bank/requirements.md](../requirements.md).

## Use Cases

- Filter recent structured server events by time, severity, component, event
  code and exact `attempt_id`/`correlation_id`.
- Open FT-008 by `attempt_id` from an event carrying paired Attempt identities.
- See an important uncorrelated server error or lifecycle transition without an
  invented Attempt association.

## Acceptance Criteria

### FT-009-AC-001 — Bounded server-event search

- REQ: REQ-LOG-001
- Observable criterion: An authorized developer searches recent structured
  server events by time, severity, component, event code and exact
  `attempt_id`/`correlation_id`, then navigates by `attempt_id` from a record
  carrying paired identities to FT-008; the browser crosses the project backend
  and never connects directly to PostgreSQL. Operator, photographer and
  unauthenticated access is denied.
- Verification: Seed paired and uncorrelated records across each supported
  field, exercise bounded filters and FT-008 navigation, reject unsupported
  query fields, verify direct and stale URL denial for every unauthorized role,
  and inspect browser/database topology.

### FT-009-AC-002 — Isolated redacted event persistence

- REQ: REQ-LOG-001
- Observable criterion: Server-event enqueue and persistence latency/failure do
  not change or roll back capture, search, Promo or QR outcomes. One explicit
  bounded owner query may resolve an existing Attempt identity for correlation;
  when it does not resolve one, the event is uncorrelated rather than
  correlation-only. The query is not subject to the event-writer latency rule.
  Records exclude
  embeddings, credentials, auth headers/cookies/tokens, participant names,
  commercial Photo originals, personalized session data, images, request
  bodies, arbitrary payloads and replay; browser events are not ingested.
- Verification: Hold the diagnostics writer and inject queue/database failure
  while checking unchanged owner outcomes; permit explicit owner correlation
  queries and run schema/redaction checks over every emitted event type.

### FT-009-AC-003 — Server-event expiry

- REQ: REQ-DATA-001, REQ-LOG-001
- Observable criterion: Structured server-event records expire after 30 days
  and stale result links cannot recover deleted event content.
- Verification: Apply cleanup around the cutoff and query current plus stale
  routes while inspecting the latest cleanup outcome.

### FT-009-AC-004 — Searchable uncorrelated events

- REQ: REQ-LOG-001
- Observable criterion: A structured server event without an applicable Attempt
  association carries neither identity and remains searchable without inventing
  one; an associated event carries paired identities and links only to the
  existing core Attempt by `attempt_id`.
- Verification: Search paired and uncorrelated fixtures and prove that FT-008
  navigation is present only for the paired shape; no one-sided fixture or
  correlation-query navigation is required.

## Edge and Failure Behavior

- Server-event persistence failure does not change or roll back a critical
  participant outcome. Covered by `FT-009-AC-002`.
- A structured event without an applicable attempt correlation remains
  searchable without inventing an attempt association. Covered by
  `FT-009-AC-004`.
- Expired event data cannot be recovered through stale result links. Covered by
  `FT-009-AC-003`.

## Explicit Non-goals

- Browser-log ingestion, full-text search and arbitrary query construction.
- Live tail, dashboards, exports, saved queries and diagnostic read models.
- A separate log datastore, search service or general observability platform.
