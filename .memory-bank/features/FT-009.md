# FT-009 — Minimal Server Events

**Epic:** [EP-003 — Explainable Diagnostics and Calibration](../epics/EP-003.md)

## Outcome

An authorized developer can inspect recent important redacted server events in
one minimal web page and navigate from a correlated event to FT-008 without
impact on the participant-critical flow.

## Requirements

- `REQ-LOG-001`.
- Cross-cutting: `REQ-DATA-001`, `REQ-ARCH-001`.
- Registry: [.memory-bank/requirements.md](../requirements.md).

## Use Cases

- Filter recent structured server events by time, severity, component, event
  code and exact `attempt_id`/`correlation_id`.
- Open FT-008 from a correlated server event.
- See an important uncorrelated server error or lifecycle transition without an
  invented Attempt association.

## Acceptance Criteria

### FT-009-AC-001 — Bounded server-event search

- REQ: REQ-LOG-001
- Observable criterion: An authorized developer searches recent structured
  server events by time, severity, component, event code and exact
  `attempt_id`/`correlation_id`, then navigates from a correlated record to
  FT-008; the browser crosses the project backend and never connects directly to
  PostgreSQL. Operator, photographer and unauthenticated access is denied.
- Verification: Seed each supported field, exercise bounded filters and FT-008
  navigation, reject unsupported query fields, verify direct and stale URL
  denial for every unauthorized role, and inspect browser/database topology.

### FT-009-AC-002 — Non-blocking redacted logging

- REQ: REQ-LOG-001
- Observable criterion: Server-event emission and persistence failure do not
  block capture, search, Promo or QR. Records exclude embeddings, credentials,
  auth headers/cookies/tokens, participant names, commercial Photo originals,
  personalized session data, images, request bodies, arbitrary payloads and
  replay; browser events are not ingested.
- Verification: Inject logging latency/failure through critical flows and run
  schema/redaction checks over every emitted event type.

### FT-009-AC-003 — Server-event expiry

- REQ: REQ-DATA-001, REQ-LOG-001
- Observable criterion: Structured server-event records expire after 30 days
  and stale result links cannot recover deleted event content.
- Verification: Apply cleanup around the cutoff and query current plus stale
  routes while inspecting the latest cleanup outcome.

### FT-009-AC-004 — Searchable uncorrelated events

- REQ: REQ-LOG-001
- Observable criterion: A structured server event without an applicable Attempt
  correlation remains searchable without inventing an Attempt association; a
  correlated event links only to the existing core Attempt.
- Verification: Search correlated and uncorrelated fixtures and inspect whether
  FT-008 navigation is present only when the correlation is known.

## Edge and Failure Behavior

- Server-event persistence failure does not block a critical participant flow.
  Covered by `FT-009-AC-002`.
- A structured event without an applicable attempt correlation remains
  searchable without inventing an attempt association. Covered by
  `FT-009-AC-004`.
- Expired event data cannot be recovered through stale result links. Covered by
  `FT-009-AC-003`.

## Explicit Non-goals

- Browser-log ingestion, full-text search and arbitrary query construction.
- Live tail, dashboards, exports, saved queries and diagnostic read models.
- A separate log datastore, search service or general observability platform.
