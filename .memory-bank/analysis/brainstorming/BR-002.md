# Brainstorming Report - BR-002

## Status

- Date: 2026-07-17
- Facilitator: AI
- Source of product intent: user
- Continues: [BR-001](BR-001.md)
- Recommended next step: /brief

## Problem Space

Первый Face Moment pilot должен проверить короткую техническую и продуктовую
петлю:

```text
authenticated web ingest
→ searchable photos
→ полностью автоматический sensor-triggered reference capture
→ четыре персональные фотографии на Promo display
→ QR continuation на телефоне
```

Оплата и фактическое скачивание полного пакета не являются gate первого pilot,
но направление будущего paid flow уже определено: одна фиксированная сумма за
полный пакет всех фотографий всех лиц, распознанных в reference-серии.

## Goals

- Проверить, что автоматический Promo привлекает внимание без действия
  посетителя и показывает найденные фотографии.
- Проверить полный путь от свежего web upload фотографа до searchable inventory.
- Показать QR-result меньше чем за 10 секунд после готовности reference-серии.
- Продолжить найденную session на телефоне без повторного selfie.
- Собрать воспроизводимые diagnostic artifacts для настройки камеры, pipeline,
  thresholds, UX и latency.

## Constraints

- Посетитель не нажимает кнопку, не сканирует trigger и не выполняет другое
  действие до автоматического capture и публичного Promo.
- Первый pilot использует одну пока не выбранную СПА-площадку.
- Reference capture выполняется с дистанции 3–5 метров.
- В MVP фотограф загружает готовые JPEG только через authenticated web app.
- Яндекс Диск не входит в MVP ingest.
- Pilot заканчивается на проверенном QR continuation; payment implementation
  выполняется позднее.
- Reference frames и selfie сохраняются для диагностики и анализа.
- Diagnostic session bundles хранятся 90 дней.

## Techniques Used

- Сужение MVP вокруг самого рискованного Promo-контура.
- Разделение product decisions, configurable defaults и validation questions.
- Performance-first анализ Promo/QR и diagnostic flow.
- Constraints-first выбор display/capture baseline.
- Проектирование воспроизводимого diagnostic session bundle без отдельного
  monitoring stack.

## Raw Ideas

Ниже перечислены рабочие идеи и defaults; они не становятся требованиями до
последующего `/brief` и PRD flow.

1. Использовать 43-inch landscape display, aspect ratio 16:9 и logical viewport
   1920x1080.
2. Настроить camera profile так, чтобы лицо на дистанции 5 метров имело ширину
   не менее 150–160 pixels в исходном кадре.
3. Проверить 4K/30 FPS camera с горизонтальным field of view около 35–45
   градусов, manual/fixed focus около 4 метров и ограниченным auto gain.
4. Начать с shutter около 1/250 s и мягкого фронтального света 500–800 lux,
   уточнив значения по реальной площадке.
5. Использовать детерминированный проходной trigger, например through-beam
   photoelectric/IR sensor; конкретный SKU выбрать после площадки.
6. Поставить `RESULT_DISPLAY_SECONDS=20`.
7. Поставить `PROMO_CURSOR_SIZE_PX=48` для logical 1920x1080.
8. Запускать финальный `Chime` в первый кадр появления Promo после достижения
   полностью чёрного экрана.
9. Ограничить search deadline восемью секундами после готовности
   reference-серии, оставив до 1.5 s на визуальный переход.
10. Поставлять пять `preChime` и пятнадцать `Chime`; воспроизводить один asset на
    событие через shuffle без непосредственного повтора.
11. Использовать application volume 20% для `preChime` и 35% для `Chime`, а
    фактическую громкость калибровать на площадке.
12. Хранить audio assets локально с versioned manifest и silent fallback.
13. Для intro использовать четыре photo pulse по 300 ms и QR grow 800 ms;
    photo scale 1→1.04→1, QR scale 0.72→1.
14. Для breathing использовать photo scale 1↔1.018 и translateY 0↔−4 px с
    циклами 5.2/5.8/6.4/7.0 s; QR scale 1↔1.01 за 6.4 s; text opacity
    .88↔1 и translateY 0↔−2 px за 4.8 s.
15. QR открывает уже найденную session без повторного face capture.
16. Стартовый QR TTL — 15 минут, browser session idle TTL — 30 минут; expired
    link переводит на общий search с заполненными СПА и датой.
17. На QR landing показывать имя СПА, дату посещения, одну из четырёх Promo
    фотографий в низком качестве, количество `N` и предложение скачать весь
    пакет в хорошем качестве.
18. CTA скачивания позднее переводит на payment page; до реализации payment
    pilot проверяет только корректность landing и continuation context.
19. `N` является числом уникальных фотографий в union результатов всех лиц,
    найденных в reference-серии.
20. Фотограф создаёт authenticated web batch сразу после окончания очередной
    серии фотографий, выбирает СПА/дату, загружает JPEG и подтверждает batch.
21. Стартовая системная цель `ingest_to_searchable_p95` — меньше 15 минут после
    подтверждения batch; отдельно измеряется задержка от съёмки до подтверждения.
22. При camera, sensor, network или processing failure display остаётся на
    локальной рекламе, отбрасывает stale request и создаёт diagnostic event.
23. Каждая попытка получает единый `diagnostic_session_id/correlation_id`.
24. Diagnostic bundle содержит исходную reference-серию, selfie, нормализованные
    изображения, выбранные face crops и screenshot реально показанного Promo.
25. Versioned `diagnostic-session.v1.json` связывает camera/config metadata,
    timestamps, pipeline revision, face detections, quality values, search
    candidates, thresholds, selected photo IDs, timings, UI/audio assets и QR
    continuation event.
26. Изображения хранятся в object storage, embeddings и индексируемые
    события — в PostgreSQL, технические логи — как structured JSON.
27. Для результата сохраняются technical outcome/status и issue tags для blur,
    lighting, pose, timeout, camera, network и threshold problems.
28. Отдельные полезные cases можно вручную перенести из 90-day diagnostic
    retention в долгоживущий calibration/benchmark dataset.

## Clusters / Themes

### 1. Frictionless public discovery

Sensor, reference capture, search и Promo работают автоматически. QR переносит
контекст на телефон, но не заставляет посетителя повторять selfie в pilot flow.

### 2. Fresh authenticated supply

Фотограф использует только web app и загружает JPEG сразу после каждой
законченной серии. Prompt ingest является частью ценности Promo, а не отдельной
административной функцией.

### 3. Package continuation

Четыре фотографии на display являются teaser. Телефон показывает одну
low-quality фотографию и размер полного пакета, составленного как union всех
фотографий всех распознанных reference-лиц. Будущая покупка имеет одну
фиксированную цену за пакет.

### 4. Reproducible diagnostics

Raw capture data, pipeline/config identity, intermediate face/search decisions,
display evidence и technical status связываются одним session ID. Это позволяет
воспроизвести полный технический путь, а не только увидеть текстовый log.

### 5. Small controlled pilot

Pilot использует двадцать повторяемых проходов знакомых тестировщиков вместо
статистически значимого полевого исследования. Он проверяет работоспособность и
основные performance characteristics текущего контура.

## Selected Directions

Подтверждено пользователем:

- первый pilot проверяет `ingest → Promo → QR continuation` без готового paid
  flow;
- capture и публичный Promo происходят полностью автоматически;
- после QR телефон сразу открывает continuation page без повторного selfie;
- landing содержит СПА, дату, одну low-quality Promo-фотографию, `N` и CTA для
  скачивания полного пакета;
- будущий paid product продаёт полный пакет за одну фиксированную сумму, а не
  отдельные фотографии;
- пакет объединяет фотографии всех лиц, распознанных в reference-серии;
- pilot использует 43-inch landscape/16:9/1920x1080 baseline и capture distance
  3–5 метров;
- в MVP ingest выполняется только фотографом через authenticated web app;
- фотограф загружает JPEG сразу после окончания серии;
- acceptance run содержит 20 поисков; одни и те же тестировщики могут проходить
  многократно;
- reference frames и selfie сохраняются для отладки;
- diagnostic retention составляет 90 дней.

Рабочий acceptance criterion для этих двадцати контролируемых попыток:

- минимум 19 из 20 попыток дают полностью видимый и сканируемый QR менее чем за
  10 секунд от `reference_series_ready_at`;
- QR landing во всех завершённых попытках показывает правильные СПА, дату и
  согласованные с той же session teaser и количество фотографий пакета;
- timeout/no-match без завершённого QR остаётся performance failure.

## Rejected Directions

Для первого MVP/pilot отвергнуты:

- Яндекс Диск и другие external ingest channels;
- pilot gate, требующий завершённой оплаты, чека, refund или реального download;
- действие посетителя для запуска capture;
- повторное selfie после QR;
- продажа отдельных фотографий поштучно;
- acceptance sample из 300 поисков и 100 уникальных участников;
- немедленное удаление reference frames и selfie после inference;
- только текстовые logs без воспроизводимого image/session context.

## Assumptions

- У каждого тестировщика заранее есть минимум четыре searchable фотографии,
  поэтому все двадцать acceptance attempts ожидаемо успешны.
- Одна low-quality фотография на landing выбирается из четырёх показанных Promo
  фотографий детерминированно; точное правило можно определить в `/brief` или
  UI design.
- `N` считается по уникальным `photo_id`; повторные detections одного лица и
  фотографии с несколькими найденными лицами не увеличивают число повторно.
- Exact camera, lens, sensor и lighting SKU выбираются после появления данных о
  реальной площадке; приведённые числа являются validation profile, а не
  подтверждёнными hardware requirements.
- Двадцать повторных попыток достаточно для технического smoke pilot, но не
  подтверждает target capacity или production readiness.
- Предложенные animation, audio, TTL и latency values являются стартовыми
  configurable defaults и уточняются по фактическому display и площадке.

## Open Questions

   ограничения будут у первой площадки?
2. Какие camera, lens, passage sensor и lighting equipment выполняют face-size,
   blur, pose и exposure profile на дистанции 3–5 метров?
3. Какой экран и error state показываются после истечения QR/session TTL?
4. Как будут устроены payment provider, fixed package price, receipt, refund,
   paid order retention, повторное скачивание и фактическая выдача originals?
5. Как будет проходить более крупная field validation после smoke pilot из 20
   попыток перед автоматическим показом реальным посетителям?
