# EP-003 — Explainable Diagnostics and Calibration

## Value

The operator can understand outcome and latency without sensitive access, while
an authorized developer can inspect available correlated evidence and explicit
gaps, record ground truth and derive explainable recommendations without
automatic serving changes.

## Features

- [FT-007](../features/FT-007.md): Core Attempt and best-effort diagnostic
  evidence.
- [FT-008](../features/FT-008.md): Role-scoped Attempts investigation.
- [FT-009](../features/FT-009.md): Minimal developer-only structured server
  events view.
- [FT-010](../features/FT-010.md): Person/detection ground-truth annotation.
- [FT-011](../features/FT-011.md): Explainable threshold and input-quality
  Calibration.

## Success Metrics

- Every server-admitted controlled request, including failures, has a core
  correlation identity and stage timeline; missing detailed evidence is visible
  as `incomplete`, while client-only offline attempt delivery is best-effort.
- An operator sees only sanitized outcome/timing evidence; an authorized
  developer can inspect available Attempt evidence and separately search the
  bounded server-event view, while missing detail remains `incomplete`.
- Calibration exposes all required threshold profiles, one-dimensional quality
  recommendations and contributing-attempt evidence without changing serving
  settings automatically.

## Acceptance Criteria

- FT-008 provides complete investigation value for one Attempt; correlated
  FT-009 server events navigate into it without absorbing annotation,
  Calibration, artifacts or specialized diagnostics.
- Logging is non-blocking and follows the content-specific media and protected
  data boundaries.
- Annotation semantics support correct, false and missed calculations at
  person/detection level.
- Structured server events, ordinary attempt/evidence data and promoted
  Calibration subsets follow their distinct retention and privacy rules.
- A Calibration run may delay the shared background worker; restart marks it
  interrupted/failed, resumes photo work and leaves rerun manual.
- Operator, photographer and developer access remains separated according to
  the PRD authorization contract.

Feature-level acceptance closure is owned by `FT-007-AC-001..007`,
`FT-008-AC-001..005`, `FT-009-AC-001..004`, `FT-010-AC-001..005` and
`FT-011-AC-001..008`, each with its governing `REQ-*` and verification method.
