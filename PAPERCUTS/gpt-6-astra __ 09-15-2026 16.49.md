- `src/face_moment/promo/realtime_orchestration.py::_is_unacceptable_query` проверяет только literal `unacceptable_query`, исключая `low_quality`. # Штатный timer очистки не активирован на локальном стенде

- Read-only проверка `systemctl is-enabled face-moment-retention-cleanup.timer` вернула `not-found`, `is-active` — `inactive`.
- Существующий cleanup реализован, но `rg --files deploy` подтвердил отсутствие указанных в runbook source units. В рамках capture identity делегировано восстановление только двух ранее описанных файлов service/timer; автоматическое физическое удаление на этом хосте требует их установки/включения при разрешённом запуске. Новый scheduler не нужен.
- В рамках реализации capture identity запуск/перезапуск рабочего стенда запрещён оператором; timer не активирован, требуемое действие передано в инструкцию запуска.
- После явного уточнения оператора о локальном применении units установлены в user systemd, timer включён с override на `.env.testing` и Docker Desktop. Ручной запуск cleanup не выполнялся.

# СОЗДАНИЕ ВТОРОЙ ПЛОЩАДКИ БЛОКИРУЕТ СЛЕДУЮЩИЙ СТАРТ MODEL CONSUMERS

- `IngestTargetRepository.resolve_committed_serving_target` требует ровно одну активную площадку (`limit(2)`, проверка `len != 1`). `entrypoints/model_consumers.py` вызывает его при связывании модели для realtime/background-worker.
- Новая активная площадка через админку сделает следующий запуск model consumers неуспешным даже при общей model revision. Создание площадок нельзя выпускать отдельно от согласованной коррекции этого ограничения. Создание данных и изменение runtime остановлены до согласования границы.

- Два теста `tests/processing/test_background_worker_runtime.py` не доходили до worker: создавали Photo без обязательного `admission_pipeline_revision_id`. В рамках обязательной проверки сохранения обработки фотографий fixtures дополнены фактической revision; оба теста проходят с PostgreSQL и MinIO.
- `test_spa_rename_persists_in_staff_selectors_and_preserves_identity` ожидает `<select id="recent-statistics-spa-id">` на `/staff/photo-inventory`, которого уже нет в текущем HTML. Проверка переименования в БД проходит, падение относится к прежнему селектору. Не исправлено в задаче переноса similarity threshold: код медиатеки и её интерфейс не входят в эту правку.
- HTTPS body-cap regression использовал старые 11 MiB при действующем Caddy cap 101 MiB (принятый upload limit 100 MiB). Тестовый Content-Length приведён к текущему cap; поведение proxy/upload не менялось.
