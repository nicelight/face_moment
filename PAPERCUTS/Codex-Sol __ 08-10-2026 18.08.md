- A verifier-owned ASGI probe helper assumed every response body was JSON and
  failed on the required HTML staff login page. Decode by content/use only the
  status for HTML routes; the probe's disposable database cleanup still ran.
- The command safety wrapper rejected an otherwise bounded disposable Docker
  proof before execution because its exact-resource cleanup function contained
  `rm -f`. Use `docker stop`/`docker rm` and `unlink` for these verifier-owned
  resources so the whole command is accepted without weakening cleanup checks.
- A loopback HTTPS readiness poll printed one transient TLS EOF while isolated
  Caddy was still starting even though the bounded retry then passed. Suppress
  expected poll stderr or probe container readiness first so successful output
  is not visually mixed with a harmless startup failure.
- An internal client connecting to Caddy by Docker alias `caddy` received a TLS
  alert even with certificate verification disabled because the configured site
  requires SNI `localhost`; changing only the HTTP `Host` header is insufficient.
  For cross-container edge probes, open the socket to the alias but wrap TLS
  with `server_hostname="localhost"`, and print observations before assertions.
