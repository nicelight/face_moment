# Workflow papercuts

- Docker build resolved the OpenCV 5 wheel but failed on the pre-existing
  dependency resolution gap for `uvicorn==0.35.0`; a subsequent Docker CLI
  probe found the configured daemon socket unavailable. This blocked the
  container-native verification path without indicating an OpenCV failure.
- The local image-inspection helper rejected an unsupported low-detail option;
  the next inspection uses its documented high/original detail values.
- The host Python is 3.14, so the project's pinned NumPy 1.26.4 has no
  compatible wheel and the isolated fallback attempted a source build; that
  temporary install was cancelled before changing the project environment.
- The minimal Python 3.11 smoke venv lacks the project's unrelated runtime
  packages, so broader adapter test collection stops on `argon2`/`boto3` before
  reaching OpenCV assertions; the focused OpenCV test remains green.
- The shell safety layer rejected cleanup of the explicitly scoped temporary
  venv via `rm -rf`; the temporary path is outside the project and remains
  recoverable for the environment owner to remove.
- The host command used `python`, which is not installed; the project host
  exposes `python3` instead.
- A compact inline Python hash command had mismatched parentheses; it was
  replaced with an equivalent heredoc read-only calculation.
- A delegated-agent call rejected supplying both `message` and `items`; the
  retry used the supported plain-message form and spawned the reviewer.
- A protocol patch initially targeted text from a neighboring evidence file;
  the context was re-read and the append was applied to the correct files.
