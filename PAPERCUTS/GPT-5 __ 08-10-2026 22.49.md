# Papercuts

- `docker compose run --rm backend python -m pytest <new-test-path>` runs the
  previously built image rather than a bind-mounted checkout. A newly added
  test is absent until the relevant image is rebuilt; the resulting pytest
  exit 4 is setup friction, not a behavioral test result.
- A source change invalidates the package-wheel Docker layer, and rebuilding
  then downloads transitive build dependencies (including `insightface`) even
  when the prior runtime image was healthy. A temporary read-only source mount
  can establish the local GREEN probe while the exact-image gate rebuilds.
- One large `apply_patch` handoff update failed its context match without
  changing files. Re-read the live protocol and apply smaller scoped patches.
- The exact image rebuild later failed outside the task after a long
  `files.pythonhosted.org` read timeout downloading `onnxruntime`. That leaves
  chained exact-image test commands unstarted; preserve the concrete network
  failure and do not misclassify it as a source/test failure.
