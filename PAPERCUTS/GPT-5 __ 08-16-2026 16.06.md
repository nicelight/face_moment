# Papercuts

- `apply_patch` rejected two large protocol patches because one expected line
  differed from the actual wrapped file content; splitting the edits into
  smaller exact patches resolved it.
- The repository uses `compose.yaml`, not `docker-compose.yml`; the first
  read-only lookup used the wrong filename and was immediately corrected.
- The host does not provide a `python` executable; the claim-specific RED
  probe was immediately rerun with `python3`.
- The source package is not installed in the host interpreter; the same
  read-only probe was rerun with the repository's `PYTHONPATH=src`.
- The host interpreter also lacks project dependencies (`fastapi`); the probe
  is routed through the existing backend Compose image only.
- A large implementation patch had one stale `__init__.py` context line; no
  files were changed by that failed patch, and the change was split into
  smaller exact patches.
