# Motion Atlas integration

- Исправлено: Fluid с повторяющимся radial-gradient давал прямоугольные швы
  на мобильном hero. Использованы неповторяющиеся пятна с прозрачными краями.
  Первичное доказательство: `.protocols/motion-atlas-qa/public-_site-mobile.png`.
- Публичный поиск по селфи и оплата отсутствуют в текущем backend. Это
  обнаруженная граница объёма: интерфейс `/site` явно помечен как предзапуск,
  отправка фото не имитируется. Требуется отдельная реализация продукта.
- Исправлено: общий CSS-селектор ссылок перекрывал цвет текста кнопки в hero,
  оставляя светлый текст на мятном фоне. Снижена специфичность базового селектора.
- При ручной загрузке uploader показывает только `rejected`, скрывая причину
  отказа. Для `/tmp/!datasets/serg_1/me_1/IMG_20230523_185218.jpg` read-only
  проверка штатным валидатором в работающем backend доказала
  `decoded_side_exceeded`: JPEG 4608×3456 при лимите стороны 4096;
  6 363 178 bytes укладываются в лимит 10 MiB. EXIF orientation=3 допустим.
  Исправлено по запросу оператора: uploader выводит безопасное объяснение
  JPEG-отказа с действующим лимитом; пустой ответ proxy 413 получает пояснение
  размера. Покрыты шесть кодов валидатора и JS fallback для не-JSON ответа.
- Подтверждено на шести загруженных портретах: SFacePhotoAdapter передаёт
  YuNet исходное разрешение без масштабирования. Пять Photo получили
  no_faces, только _logo.jpg 200×200 стал searchable. Read-only повтор в
  background-worker на тех же originals и той же YuNet при рабочем размере
  до 640 px (INTER_AREA, без повышения размера маленьких кадров) обнаружил
  по одному лицу на всех шести, включая исходный EXIF-oriented JPEG и его
  повёрнутую копию. Порог не изменялся. Локальная матрица original/1280/640/320:
  `.protocols/model-debug/yunet-scale.log`. Требуется исправление preprocessing
  с сохранением координат оригинала и совместимости pipeline revision;
  масштаб 640 подтверждён только на этом наборе крупных портретов.
