# Session Papercuts

- Объединённый priming-вывод `exec_command` был обрезан при чтении нескольких governing-файлов; надёжный обход — читать обязательные документы небольшими адресными срезами.
- `collaboration.wait_agent` отклоняет `timeout_ms` меньше `10000`, хотя короткий poll был бы удобен; минимальное допустимое значение нужно учитывать заранее.
- Первый task Reviewer был создан с full-history fork без явного model override; его пришлось немедленно остановить и перезапустить с `fork_turns: "5"`, `gpt-5.6-sol`, `xhigh`, чтобы выполнить operator-prescribed worker assignment.
- Первый `/red-verify TASK-005` turn был прерван ложным platform cybersecurity filter на штатной credential/session semantic-проверке; durable verdict не появился, хотя worker успел создать task-local probe, поэтому recovery требует сначала сверить частичный артефакт и повторить только безопасную незавершённую semantic стадию.
- Compose предупредил, что `--progress` является global flag: вместо `docker compose build --progress=plain backend` следует использовать `docker compose --progress=plain build backend`.
- Один `functions.exec` poll упал на JavaScript `SyntaxError` из-за лишней кавычки в `yield_time_ms`; running Docker session сохранилась, корректный повторный poll продолжил тот же build без влияния на процесс.
- `.memory-bank/tasks/index.json` не хранит task status inline: быстрый `jq` projection вернул `null`, поэтому authoritative status нужно читать из соответствующих `.task.json` records или doctor queue summary.
- Первая попытка дописать предыдущий papercut через `apply_patch` не совпала с фактической русской формулировкой последней строки; адресный reread файла позволил применить точный patch.
- Три последовательные current-source Docker builds для TASK-009 были сорваны внешним PyPI: один incomplete-index response не вернул `greenlet`, затем два `files.pythonhosted.org` read timeout на крупных wheels. Без изменения репозитория помог эквивалентный transient Dockerfile stream с builder-only `PIP_DEFAULT_TIMEOUT=1000`; он потребовал cold builder toolchain layer, но завершил image build.
- Первый запуск incremental `docker build --file -` для TASK-012 ожидал Dockerfile на stdin, потому что wrapper подготовил строку в JavaScript, но не передал её процессу. Сессия сохранилась; Dockerfile и EOF были отправлены через `write_stdin`, после чего build завершился без перезапуска.
- Full dependency-aware build для TASK-016 дважды сорвался на внешней доставке артефактов: сначала `scipy` read timeout, затем после extended-timeout recovery один 48 KB wheel пришёл с SHA mismatch. Поскольку `pyproject.toml` добавлял ровно один pinned `python-multipart==0.0.20`, надёжным bounded recovery стал image поверх последнего reconciled runtime: явно установить только этот dependency delta, скопировать полный текущий runtime/test/config surface и переустановить project wheel без повторного разрешения неизменного тяжёлого ML graph.
